# Retail Analytics

The separate **Analytics** module opens from the portfolio toolbar or empty-state actions. Its two visible views are **Overview**, which brings together the summary and all product, retailer, category and price-positioning charts, and **Data**, which provides searchable detail rows and filtered CSV export. The compact top navigation gives the reporting controls, large quantities and borderless charts the full canvas width.

Planning cards, the shortlist editor and brief exporters remain implemented for a later planning workflow. Their **Plan** navigation and **Export brief** action are hidden in the current presentation.

## Data and refresh

Import an ordinary XLSX workbook, wide or tidy CSV, saved analytics JSON snapshot, or protected analytics `.pkg`. The workbook reader accepts weekly Account, HP SKU, Product Description, Category and Lifetime tables. It reads cached formula values and never executes workbook formulas, macros or external links. If multiple worksheets contain matching tables, select the intended worksheet in the import review.

**Load workbook** opens the local file picker directly, in both the header and empty state. The Load data dropdown and SharePoint link entry are hidden for now. Local imports retain their review and **Apply workbook** step.

The retained SharePoint implementation recognizes HTTPS SharePoint Excel workbook links. When that feature is restored with an approved connection, an explicit Load action signs the user in through Microsoft's popup if needed, downloads a temporary copy, and validates it with the same bounded XLSX reader. One matching worksheet loads directly; multiple matching worksheets require a worksheet choice. No approved Microsoft application has been supplied yet, so the committed source configuration remains disabled and the feature has no visible entry point. A separate SharePoint sign-in does not connect PPC. Temporary signed download URLs and authentication tokens are excluded from reports, backups and build logs.

The import review shows the source, reporting dates, row counts, totals and adjustments before applying a local file. Importing or loading changes only the analytics workspace. Its browser database is `ppc-retail-analytics-v1`; portfolio packages, master facts and roadmap dates are independent. Imported datasets, price maps and planning shortlists remain local. SharePoint retrieval runs for an explicit Load action; it introduces no recurring refresh, backend polling or Supabase dependency.

### SharePoint connection setup

An HP Microsoft Entra administrator must approve and register the connection before real sign-in can work. Register a single-tenant browser application for the authorized organization, add the **Single-page application** platform, and register this exact production redirect URI:

`https://monocraft.github.io/PPC/analytics-auth.html`

Configure delegated Microsoft Graph **Files.ReadWrite** for the shared-link resolver and obtain consent required by the organization's policies. Microsoft's Shares API lists this write-capable scope as its least privileged delegated permission. The PPC integration uses GET requests to read the requested workbook; it does not turn that permission into file editing, permission management or master updates. This distinction must remain clear when IT approves consent. No client secret or certificate belongs in this browser application. [Microsoft Graph shared-item permissions](https://learn.microsoft.com/en-us/graph/api/shares-get?view=graph-rest-1.0).

Set these three nonsecret **GitHub Actions repository variables** for the Pages deployment:

| Variable | Required value |
| --- | --- |
| `PPC_SHAREPOINT_CLIENT_ID` | The approved application's Application (client) ID, in nonzero GUID form. |
| `PPC_SHAREPOINT_TENANT_ID` | The organization's Directory (tenant) ID, in nonzero GUID form. |
| `PPC_SHAREPOINT_HOSTS` | A comma-separated list of exact authorized hostnames, including the organization's `-my.sharepoint.com` host when personal workbooks are needed. |

Hosts must be organization labels ending in `.sharepoint.com`. Wildcards, URLs, paths, ports, credentials, duplicate entries and broader domains are rejected. With all three variables absent, `scripts/configure-sharepoint-source.mjs` emits a disabled configuration. Partial or invalid settings fail before creating or replacing `_site/js/sellout-sharepoint-config.js`. Public identifiers and the host allowlist are the only generated values; authentication tokens, secrets and workbook links are not configuration inputs. The committed `public/js/sellout-sharepoint-config.js` always remains disabled.

The browser uses locally packaged **MSAL Browser 5.25.1** and a dedicated `analytics-auth.html` callback page. Registering a different callback path will not work. The callback runs the MSAL redirect bridge without loading analytics, portfolio, master or routing code. MSAL's access-token cache uses memory storage. Graph metadata requests carry the bearer token only to Microsoft Graph; workbook bytes are fetched from the returned temporary download URL without that token. Microsoft documents this two-step browser download because the authenticated `/content` redirect is incompatible with a CORS preflight. [MSAL redirect bridge](https://learn.microsoft.com/en-us/entra/msal/javascript/browser/redirect-bridge), [MSAL caching](https://learn.microsoft.com/en-us/entra/msal/javascript/browser/caching), [Graph browser downloads](https://learn.microsoft.com/en-us/graph/api/driveitem-get-content?view=graph-rest-1.0).

Local fixtures can verify configuration, mocked sign-in and download boundaries. Actual organization sign-in, consent, conditional-access behavior and workbook retrieval have not been verified without the approved application. After IT setup, a bounded owner-authorized connection test is still required; passing syntax or mocked tests does not establish production SSO.

The retained **Save analytics snapshot** action in the hidden planning workflow produces a private local JSON backup. It includes source data, manual USD MSRP mappings, PPC pricing provenance and the planning shortlist, including its owner, proposed roadmap month and notes. JSON imports and exports validate the analytics schema and remove unrelated fields. This file is plaintext and must stay outside the published site. Browser storage may be unavailable or cleared, so retain an encrypted package for work you need to keep.

The encrypted export uses the existing PPC package key format and codec. Enter the authorized team's existing key in the encryption dialog, save `retail-analytics.pkg`, and keep the key separate. Opening that protected file requires its key and then presents the normal import review. A wrong key, modified ciphertext, plaintext ZIP or portfolio package cannot be treated as an analytics workspace. The key is cleared from the dialog after each attempt and on close; the export helper does not read browser credentials, send requests or write the portfolio master.

Protection applies to the exported file. An unlocked analytics workspace is still saved as device-local data in the browser profile; encrypted export does not retroactively encrypt or erase that local copy.

## Comparisons and coverage

- Missing cells remain `null`. Real zero quantities and negative adjustments remain numeric. Net totals sum reported observations, and weekly pace divides by the number of weeks with observations.
- Shared retailer cutoff stops at the earliest last observed date among the selected retailers and selected SKUs. This aligns the end date; it does not assert that every SKU reports in every earlier cell. **All available reports** retains later, potentially partial periods.
- Same-weeks-last-year comparison uses exactly 364 days. Previous-period comparison shifts by the complete selected calendar span plus seven days, so gaps in imported weekly columns cannot produce overlapping windows.
- Delta and percentage growth use paired numeric observations for the same retailer and SKU. An incomplete comparison calendar suppresses change metrics. Growth also requires a positive paired baseline. Raw current/comparison totals may differ from paired totals when cells are missing.
- Fiscal comparisons use source fiscal-year/quarter labels and exact 364-day date alignment. Cropped or shifted imports retain their actual fiscal-year labels. Tidy CSVs without fiscal labels use the importer's November fiscal start convention.
- SKU is the product identity; retailer-specific descriptions remain in the detail rows, and aliases are searchable. Conflicting duplicate retailer–SKU rows are rejected. Exact repeated import rows are omitted with a visible warning.
- Date-header corrections require two adjacent weekly labels that support one replacement. Original labels and correction notes remain visible in source details.

Category mix uses positive category totals for its percentage denominator. Signed quantities remain intact in all net totals and signed bar charts. Its wide, borderless diagram and contribution bars animate to the selected scope. Hover or keyboard focus shows the category's exact units and share in the diagram center; selecting a category filters the dashboard, and **Other** expands the full category list. Small positive shares below 0.1% retain their actual bar widths and display **<0.1%**. The momentum chart uses a compressed signed scale for growth to keep large outliers and smaller movements visible; exact values are available in details.

**Retailer × category** uses a fluid ribbon diagram. Each ribbon's width represents a positive aggregate retailer–category net quantity, with balanced quantities at both ends. Its denominator is the sum of those positive pairs, which can differ from category net totals when negative pairs exist. Negative aggregate pairs retain their signed evidence and remain excluded from widths. Reported zero pairs, missing pairs and absent pairs stay distinct. Hover or keyboard focus reveals exact pair quantities; selecting a regular ribbon filters its retailer and category, while **Other** expands the remaining categories. The price-band chart retains its neutral grid.

The weekly chart starts in **Retailers** view. Three native buttons switch between **Retailers**, **Total** and **SKUs**, without a dropdown. Selecting products draws one trend line for every selected SKU; an unfiltered SKU view shows the top five. Complete Total comparisons use matched current/baseline observations, while retailer and SKU lines retain their reported quantities and missing-week gaps. Compared retailer bars also use matched totals and explicitly label their axis.

Large retailer numbers above the chart show the observed weekly quantities for the active reporting label, using the same retailer, product and category filters as the analysis. Hover updates the readout; clicking or dragging pins a weekly marker. Arrow keys, Home and End move it between the actual source labels, and its clear action restores the unpinned readout. Reported zero, missing and negative quantities remain distinct. A pinned date outside a changed window snaps to the nearest available source label.

The timeline supports weekly stepping, playback and dragging its start, end or whole window. Borderless month buttons use the same weekly-index positions as the history track and selection handles. Month labels sit at their selectable range midpoint, including reporting-cutoff clips. Each year label sits directly above its first displayed month label, while the subtle year divider stays at the source boundary. On narrow screens, the track and labels move together on one horizontal calendar canvas; an offscreen selected range centers in that shared viewport. Tiny partial months hide only their visual label and retain their full native title and accessible description. Reported zero remains distinct from missing months, and keyboard focus stays on the chosen month.

Finite motion uses the currently displayed chart positions when a range changes again; pinned point markers follow those same animated positions. A bounded spring adds a gentle plot translation/scale during range interaction and returns to rest. This effect changes display geometry only; source weeks and quantities remain unchanged. Reduced motion renders the final geometry immediately.

**Reporting** uses the same neutral shaded-cell style as **Price bands**, with fixed retailer rows and one column for each selected source week. Lighter shades show larger positive net quantities on one scale shared by the visible retailers. Negative adjustments retain signed quantities and the alert color. Reported zero remains an explicit numeric value, while a missing report shows a quiet dash without a quantity. Hover or keyboard focus highlights the week column and shows that week's exact quantities across all selected retailers. Retailer labels and table geometry stay fixed. Clicking a cell or activating its native button with Enter pins the exact reporting date on the main chart. Left and right arrows move between weeks, up and down move between retailers, and Home and End move to the first and last week in the row.

The top navigation replaces a left sidebar, and the main chart spans the borderless canvas. Retailer lines use distinct white, blue, teal and yellow tones; SKU lines use six distinct chart colors. The category contribution diagram uses softened derivatives of the approved PPC palette. Leading SKUs, retailer–category ribbons, the price grid, fiscal quarters and reporting lanes use neutral gray like the growth chart. Controls remain neutral and negative observations use the theme's alert red.

## Price positioning

The sell-out workbook does not supply prices. Open **Analytics** from PPC to request its current local USD MSRP projection, or open **Data & pricing** and use **Select PPC backup** to import a private PPC data backup or allowlisted pricing projection. There is no top-level PPC prices button. While the expiring PPC connection remains available, pricing refreshes in the background when the dashboard gains focus or a workbook is applied. A backup remains labeled as a backup; it does not establish that prices match the current shared master. The active PPC projection can include current local drafts, so it must also retain that authority label.

Exact normalized HP SKU matches come first. Only an unambiguous seven-character HP base part number can provide the documented country-suffix fallback. Saved product MSRP takes precedence over an exact SKU launch-tracker USD price. Conflicting source products or tracker prices remain visible and do not silently become one amount. The bridge provides pricing identifiers, USD values, evidence type and coverage; it does not transfer specifications, lifecycle dates, images, private configuration or keys.

Manual **USD MSRP / list price** entries in Data & pricing are explicit overrides. Import a CSV with `sku,msrp,source` columns or use the template for imported SKUs. Blank prices remain unmapped, zero is valid, negative or nonnumeric prices are rejected, and duplicate price keys are rejected before applying a CSV.

Bands are under $50, $50–99.99, $100–149.99, $150–199.99 and $200+. This independent map describes list-price positioning, not historical retail transaction prices. Category and band matrix tooltips show retailer shares within the selected category or band. A missing row or low quantity is an investigation hypothesis, not proof of unmet demand.

## PPC and market planning

The retained, currently hidden planning workflow summarizes reported volume leaders, paired declines and category review hypotheses. Its shortlist editor can assign an owner, proposed roadmap month and validation notes. The shortlist retains its original source and reporting period even when the dashboard filters change.

The hidden brief exporters produce PPC planning or retailer-specific market briefs. Retailer briefs recompute their totals and evidence for the chosen market using the dashboard's existing reporting window. Briefs include source context, matched comparison definitions and shortlist actions. They do not add products or commit roadmap dates automatically.

The data explorer distinguishes paired gains/declines, stable paired quantities, zero net quantities, negative net quantities, missing reports and unavailable baselines. These are measured signals; commercial success still requires target, price, availability and margin context.

## Implementation and checks

`public/analytics.html`, `public/css/sellout-dashboard.css`, the dedicated `sellout-months.css` and `public/js/sellout-dashboard.js` provide the separate interface. `sellout-model.js` calculates observed quantities and comparisons; `sellout-mix.js` calculates filtered category contribution; `sellout-flow.js` lays out balanced retailer–category ribbons; `sellout-motion.js` manages finite chart transitions; `sellout-spring.js` handles bounded presentation geometry; `sellout-ppc.js` resolves the minimal USD pricing projection; and `sellout-private.js` protects analytics-only backups. `sellout-sharepoint-config.js` provides disabled-by-default public connection settings; `sellout-sharepoint.js` validates workbook-link syntax; and `sellout-sharepoint-client.js` owns the bounded Microsoft sign-in and workbook retrieval. `analytics-auth.html` and its redirect bridge stay separate from application data and editing code. The module reuses the local Jost fonts, reference theme, bounded XLSX ZIP helpers and `PortfolioPackage` authenticated encryption. Assets are explicitly staged by site preparation and receive deployment versions on the separate HTML pages.

The pricing connection uses a 256-bit cryptographic capability generated for an explicit Analytics click. It uses an expiring, uniquely named same-origin `BroadcastChannel`, preserves `noopener`, and removes the capability fragment from the dashboard URL. Correlated requests and strict message schemas limit responses to the pricing projection. The capability expires after five minutes; each refresh is requested by the dashboard rather than sent as an unsolicited portfolio broadcast. The secret channel name is the access capability; a claimed path inside a message would not independently establish the sender's identity. This mechanism stays within the trusted browser origin and is not corporate identity authentication.

`PPCSelloutPrivate.encrypt(workspace, key)` returns encrypted package bytes, and `decrypt(bytes, key)` returns a validated, independent analytics workspace. A distinct authenticated `analytics.json` entry identifies the module and schema. The helper validates the source snapshot and pricing projection, limits data size, strips unrelated fields and stale manual price entries outside the imported SKU scope, and preserves zero, missing and negative observations. It never imports into the portfolio or changes master facts.

Run `check:sellout`, or execute the model, category mix, retailer–category flow, motion, spring, month-selection, PPC pricing, private package and module checks in `scripts/checks/`. ## Publishing and access

The current PPC site is hosted on public GitHub Pages. Publishable HTML, scripts and styles must contain no sell-out rows, private price projections, credentials or populated preview payloads. A private repository alone does not make its Pages output private. The published dashboard shell can remain public while data is supplied separately. [GitHub Pages publishing guidance](https://docs.github.com/en/pages/getting-started-with-github-pages/configuring-a-publishing-source-for-your-github-pages-site).

If the analytics audience is exactly the existing PPC key-holding team, a separately hosted encrypted analytics package can reuse that key after the owner approves the dataset and audience. Every holder of that key can decrypt the analytics package. Reusing it does not carry over SharePoint's per-user permissions, provide individual revocation, or prevent an authorized reader from exporting data. The current deployment deliberately permits only `public/data/master_ppc.pkg`; local analytics exports do not expand that allowlist or upload anything.

If Markets access is narrower, use an approved corporate identity provider and a private data API or private storage bucket with user/group authorization. Keep server credentials on the backend. Supabase private buckets enforce download access through JWT/RLS or bounded signed URLs; secret and service-role credentials bypass RLS and must never be copied into browser code. The existing PPC shared-key gateway has no corporate SSO membership check and cannot establish that narrower audience by itself. [Supabase private bucket access](https://supabase.com/docs/guides/storage/buckets/fundamentals), [Supabase function secrets](https://supabase.com/docs/guides/functions/secrets).

The local code, encrypted export and read-only pricing connection are ready for review. Publishing data, changing the deployment's data allowlist, configuring corporate SSO/private storage, or granting team access requires the actual owner authorization and the corresponding repository, hosting and identity administration access. Do not replace or reseed the accepted PPC master to add analytics.
