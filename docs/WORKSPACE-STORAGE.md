# Local workspace storage

The complete working portfolio is stored in IndexedDB beside the existing binary image library. The workspace record retains the exact serialized data, including specifications, IDs, image references, layouts, PLC evidence, local baselines, merge intents and other operational metadata. Package keys keep their existing endpoint-scoped session storage behavior; GitHub tokens remain in memory. They are not added to workspace records.

Opening waits for the saved database record before displaying products or connecting shared saving. On first migration, a valid older localStorage workspace is normalized using the existing schema rules and committed with any migrated inline images. Older localStorage records are retained, while the new database record takes precedence. A corrupt or inaccessible saved record stops opening; defaults are created only when every prior workspace record is absent.

When saved storage can still be read, the opening screen exposes recovery controls outside the disabled workspace. **Export saved data for recovery** downloads the exact saved text, including malformed JSON and its original whitespace. Choose a complete `.data` backup or `.pkg` project package, enter its access key if encrypted, and select **Review backup**. Reviewing validates the full portfolio and its local image files without writing anything. The screen shows the category and product counts before **Restore this backup** explicitly replaces the unreadable saved record. A data backup can reuse its existing image files on this device; choose a complete project package when those files are missing. Categories-only files and names-only updates are unsuitable for recovery.

Recovery reads and compares the original record inside the same transaction that commits the validated backup and any new images. A different tab's recovery or save causes a conflict instead of being overwritten. Existing images and legacy localStorage bytes remain available. The original record is also retained in the device's recovery archive. A transaction failure keeps the original record and all images. If display activation fails after commit, recovery attempts to restore the exact original record with another guarded transaction. If that restoration fails or another tab has changed the record, the screen reports it and keeps the original recovery export available; the committed backup and recovery archive remain saved. No recovery operation changes access keys or shared connection settings. When storage itself cannot be opened or read, retry opening before replacement so an unreadable record is never blindly overwritten.

Autosave captures a complete JSON snapshot and serializes writes within the tab. A save succeeds only when its transaction completes. Package and data imports commit the manifest and incoming image blobs together before activating the new portfolio. An aborted transaction leaves the previous saved copy intact. If display activation fails, restoration is awaited; if restoration also fails, imported images remain available for the committed record. PLC evidence and its sharing queue are committed before activation or shared requests.

Failed local saves show a persistent warning with retry and data-backup actions. Pending local changes trigger the browser's normal warning when closing the page. Data backups retain the full working metadata and image references; the existing portable project-package export also contains image bytes and follows its existing portable metadata rules.

Restoring a full `.data` backup preserves its supplied comparison baseline and pending metadata, so an unsaved manual edit remains a pending edit. A baseline is constructed only when the input does not provide one. Portable package imports continue to construct a fresh baseline under their existing transfer rules.

The full local workspace and `.data` backups have no application-defined size cap. Actual browser storage capacity and available memory remain finite; quota failures are reported and preserve the previous committed copy. Portable packages retain the codec's separate 64 MiB total, uncompressed and encrypted package limits, so images and the manifest must fit the complete package. Existing encrypted-master manifest and network request limits are unchanged; local storage capacity does not expand shared transport budgets.

The save queue orders snapshots within one tab and checks that a captured snapshot still belongs to the current workspace before committing. Independent tabs share the origin's saved workspace. Each observed client compares its last saved/read record with the current durable record inside a readwrite transaction. A stale tab retains its open draft and receives an actionable conflict message; export that draft before reopening and reviewing the other tab's saved changes. This protection prevents silent replacement without introducing a cross-tab merge protocol. Shared master conflict handling continues to operate separately.
