# Data backup and product name updates

Settings → Data & export includes **Copy data backup** as a fallback when the browser cannot deliver a downloaded file. It copies exactly the JSON produced by **Export data file**, including specifications, SKU and image references, settings, date history, pending metadata and the comparison baseline. Access credentials are held separately and are not part of that portfolio record. Image files remain separate from a lightweight data backup; **Export portfolio** includes those files.

Click Copy data backup, then paste into a text file and save it with a `.data` extension. The exact backup is also shown immediately in a readonly seven-line text field for manual selection and copying. The app reports success or failure in the same panel. The native clipboard request has a two-second limit, followed by the existing legacy copy fallback. A failed copy can be retried with a fresh click in the active browser window. If the portfolio changes while copying, or an obsolete native request completes after its timeout, the displayed backup refreshes and the app asks for another copy so the backup reflects the latest state.

For product name corrections, make a fresh data backup, edit only the `name` property on the relevant product records, and choose **Import name updates**. Every other field must match the currently open portfolio, including category, lane and product identities and order, specifications, SKUs, artwork references, dates, history, settings and the shared comparison baseline. Existing pending shared changes must also be names only. Stale backups and files containing other changes are rejected before any data is written.

Validated name updates are saved locally as one guarded operation, then assigned to the existing product objects. The action retains the current working portfolio, artwork and shared access; it does not replace or normalize other data, rebase the shared comparison, unlock a session, or publish automatically. Review and save the resulting name changes through the existing sharing controls.

**Import data file** continues to restore a complete workspace and keeps its existing sharing-access boundary. Import name updates is a separate, narrower action for the current working portfolio. A local save failure leaves names unchanged; if restoring a saved copy also fails, the existing recovery notice and retry-saving action remain available.
